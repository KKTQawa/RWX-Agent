# RWX RSI 自定义 AI 策略蓝图

本文保留原始设计。实际实现将同一职责合并为粗粒度回调，并将五个模块基类放入 `RsiStrategy`。当前可用签名与权限见 [编写 RWX RSI 策略](RWX_RSI_AI.md)。

实验作者可阅读原版与现有自定义 AI 源码。写入只允许 `core/src/main/java/com/corrodinggames/rts/game/ai/custom/ai_rsi/`。维护者在目录之外提供 SDK 和固定注册入口。

## 1. 唯一允许继承的策略基类

每支队伍只有一个已注册的入口，例如 `ExperimentAi extends RsiStrategy`。入口在 `configure` 安装模块，一个职责最多安装一个模块。模块的 `protected` 回调由宿主在指定节拍调用。普通辅助类、算法、评分器和状态机可自由编写，通过模块组合使用。自行实例化一个模块或调用它的回调不会发出命令。

| 允许继承 | 可覆写的方法与触发时机 | 可写策略字段和可调用能力 | 下限 → 上限 |
|---|---|---|---|
| `RsiStrategy` | `configure(registrar)` 在组装时注册模块，`onStart(view)` 初始化策略状态 | 可写开局、阶段、自身状态和模块引用。可选择模块与申请受宿主限制的回调频率 | 空入口使用默认策略 → 根据地图选择模块，在运行中调整开局、中期和后期计划 |
| `RsiEconomyPolicy` | `planEconomy(view)` 在经济节拍提出预算，`assignBuilders(view, budget)` 提出建设、扩张、维修和回收任务 | 可写预算比例、矿点优先级、扩张和风险计划。可查矿点、合法点位、建造者、到达距离和建造成本 | 只提高一处近矿的优先级 → 多基地扩张、前线设施、投资转型、撤离高风险工地 |
| `RsiProductionPolicy` | `planProduction(view, budget)` 在经济节拍提出特定生产者的队列、升级与弹药动作 | 可写目标兵力比例、补员缺口、科技路线和队列目标。可查单位动作、造价、科技前置、在产数量和队列占用 | 只改一座工厂的一项出兵选择 → 动态转产、跨厂配产、调队列、统筹升级与合法弹药生产 |
| `RsiOperationsPolicy` | `planOperations(view)` 在战略节拍提出建队、角色、分配、目标、集结点和交战约束 | 可写任务、战区优先级、预备队、侦察记忆和作战时窗。可查可见目标、地形路线和可分配兵力 | 只改一个目标 → 动态分队、多线行动、调拨预备队与制定跨岛战役计划。该模块分配任务，部队的即时命令归战术模块 |
| `RsiTacticsPolicy` | `directSquad(view, mission)` 在战术节拍运行，`react(view, mission)` 可按宿主批准的更短节拍运行 | 可写站位、撤退阈值、目标评分和技能计划。可查射程、相性、当前命令、冷却和到达能力。可提出移动、攻击移动、集火、护卫、巡逻、撤退、停止和合法技能命令 | 只替一个编队选目标 → 接管全军或逐个单位，实施迂回、拉扯、分批交战、撤退和技能协调 |
| `RsiLogisticsPolicy` | `planTransport(view, requests)` 在战术节拍调度请求，`directTransport(view, mission)` 可接管特定运输任务的路线和装卸 | 可写乘客名单、优先级、接送点和分批条件。可查兼容性、容量、装载状态和航线 | 只调配送顺序，复用原版执行 → 多段接驳、跨岛投送、撤运和补援。全过程服从游戏运输规则 |

实验入口不能自行注册难度或实现 `AiStrategy`、`AIBehavior` 等原生扩展，也不能继承 `AIController`、`BaseZone`、`UnitGroup`、`TransporterGroup`。这些类供阅读和宿主适配器复用。适配器接入 [AiRuntime](../../core/src/main/java/com/corrodinggames/rts/game/ai/strategy/AiRuntime.java) 和 [CustomAiCatalog](../../core/src/main/java/com/corrodinggames/rts/game/ai/custom/CustomAiCatalog.java)。

## 2. 字段权限、调用权限与回退

### 允许读写的字段

- **六个宿主基类不提供可写的继承字段。** 策略通过覆写回调、保存自己的字段来改变决策。SDK 的读模型和提交工具也不能继承来扩大权限。
- **策略私有状态可写。** 例如 `opening`、`lastSeen`、`squadPlans`、`retreatHpFraction`。实例按对局、队伍分开。比例限定在 0 到 1，预算与数量非负，周期为正整数游戏 tick，坐标有限且在地图内。宿主限制回调频率与每轮工作量。模块通过不可变视图共享计划，不直接写其他模块的状态。
- **引擎状态只读。** 自己的资源、单位、可用动作和队列可精确读取。对手只暴露当前可见的状态及最后已知的历史。单位消失在雾中时，记忆里的信息不随真实单位移动、升级或死亡更新。路径与选址查询也不能透出隐藏单位或建筑。句柄仅用于标识实体，不能取回底层对象。
- **对局事实由宿主固定。** 收入倍率、初始资源、科技规则、视野、游戏时间和难度基底均由宿主配置。策略能用游戏内行为改变收入、兵力、科技与版图，不能直接写对应的引擎字段。SDK 不返回 `AiContext.team()`、活的 `BaseUnit`、`Command` 或注册表。

### 调用怎样改变行为

建议把调用面固定为三个类型。 `RsiRegistrar` 仅在组装时安装模块与申请节拍。 `RsiView` 只包含值、查询和供校验的句柄。 `RsiDecision` 是回调的返回值，保存有类型的任务、候选排序或动作，策略不能把它转成底层命令或自行提交。

| 操作 | 示例 | 边界 |
|---|---|---|
| 查询 | `visibleEnemies`、`buildOptions`、`canAttack` | 只读。失去视野的单位可作为历史坐标用于区域行动，不能作为精确目标 |
| 重排候选 | 回调返回建筑位置、生产单位、招募对象或可见目标的排序 | 只重排使能范围内的合法候选。可以先复用默认执行，再写完整策略 |
| 提出长期任务 | 分队、预算预留、排产目标、运输安排 | 建立策略任务或请求，期限与交接由宿主管理。预算是计划上限，实际花费由引擎结算 |
| 提出具体动作 | 移动、攻击、建造、排队、升级、技能、装卸 | 只对有控制权的己方单位提交。走标准游戏命令，保留路径、射程、造价、冷却、数量和队列限制 |

每个受管辖的单位、编队、工厂或职责具备三种结果。

- **`DELEGATE`** 交给默认策略。空模块和所有未覆盖的范围均用默认。
- **`PROPOSE`** 提供自定义意图。通过校验并取得控制权才生效。提交前无有效提案、也无已生效的接管任务时，回退到默认。
- **`HOLD`** 在限定范围、有效期内保留当前任务，阻止新增该职责的命令。已有命令继续执行。停止或取消需要显式合法动作。接管到期、主动释放或任务结束后恢复默认。

默认模块可以直接复用已确认只用合法观测、能独立运行的原版逻辑。原版存在读取全图信息的逻辑，例如前哨评估使用敌方指挥中心坐标。此类默认逻辑必须使用合规的观察输入，再给实验策略复用。空策略要能完整运转。它与逐帧保留原版是不同的验收目标。 [AIController](../../core/src/main/java/com/corrodinggames/rts/game/ai/AIController.java) · [AiTerritory](../../core/src/main/java/com/corrodinggames/rts/game/ai/custom/util/AiTerritory.java)

## 3. 哪些环节会互相覆盖

现有原版的组更新、基地补员和闲置召回分别发命令。只控制 `UnitGroup.updateAI()` 仍会留下 `UnitGroup.updateCore()` 的应战命令。整段关闭原版战术或战略，会连带影响基地和运输。拟议宿主按实体和职责仲裁，由所有原版与自定义路径共同遵守。 [UnitGroup](../../core/src/main/java/com/corrodinggames/rts/game/ai/UnitGroup.java) · [BaseZone](../../core/src/main/java/com/corrodinggames/rts/game/ai/BaseZone.java) · [AIController](../../core/src/main/java/com/corrodinggames/rts/game/ai/AIController.java)

| 冲突 | 尽量独立的方案 |
|---|---|
| 作战调度要求推进，战术判断应撤退 | 作战层写任务和编制，战术层独占即时移动与攻击。战术允许紧急撤退，作战层于下一轮按任务状态重分配兵力；作战层不直接下移动令 |
| 原版招募、追击、基地补援或清令覆盖自定义部队 | 每个单位同一命令通道只有一个持有者。原版招募与命令跳过当前已接管的单位。保留原版的死亡清理、路径执行和单位正常自卫。接管或释放时明确保留、替换或停止旧命令，使用正常游戏动作 |
| 运输和战术同时管乘客 | 接受任务时只预留资源，开始集结装载时才移交相关移动控制权。任务负责装载、行驶和卸载。卸载后归还战术。取消须区分尚未装载和已经装载，不能把单位留在运输器里失去控制。 [TransporterGroup](../../core/src/main/java/com/corrodinggames/rts/game/ai/TransporterGroup.java) |
| 抢矿、建厂、升级与出兵都想花同一笔钱 | 经济模块制定储备与预算。全队使用同一资源账本，包括已提交待执行的订单，防止同一周期重复预留。按明确优先级和稳定次序选出可执行的意图 |
| 建造者同时收到建设、维修、回收或返防任务 | 默认归经济模块管理。作战借用须提出用途和期限。任务交接后，才能修改该建造者的顺序命令 |
| 同一工厂收到生产和升级，或同一单位收到技能和移动 | 生产和升级由生产模块统一协调并服从引擎队列。移动、攻击、护卫共享顺序命令通道。集结点、模式或技能仅在引擎允许并行时走独立通道，影响当前任务的技能参与同一仲裁 |

每轮先建立统一观察，再收集任务和命令意图，接着统一分配控制权及预算，最后以稳定顺序提交。控制权粒度是**实体加命令通道**，任务负责范围和期限。位置、资源和战况仍通过下一轮观察或显式交接影响其他模块。跨块协同保留，重复写入同一职责由仲裁处理。

重叠的编队声明先展开到单位再仲裁。例如第 5 号坦克同时被正面队和突击队请求时，先保留已生效的归属，只有显式交接、任务到期或约定的紧急抢占才可改派。同一模块内的平分候选按固定次序选择，已接受的待发命令参与预留。带先后依赖的一组意图尽量先整体校验，前一步未获准时，依赖它的动作本轮也不提交。

## 4. 怎样验收下限、上限和公平性

### 下限用一个工厂就能验收

空入口必须能正常开局、发展和战斗。进一步只安装生产模块，只在第一座闲置陆军工厂有合法选择时提高重坦权重。其余范围返回 `DELEGATE`，基地、运输、其他工厂和战斗由默认模块管理。验收时应能清楚指出哪座工厂在哪个条件下改变了决策。

### 上限用一套多线战役验收

经济模块根据暴露的矿点和威胁安排前线支出。作战模块依据侦察把军队分为正面牵制、跨岛突击和守矿三组。生产模块按战损和运输容量调整补员。运输模块接手突击队的集结和运送，卸载后交还。战术模块让牵制队继续压制、突击队独立集火或撤离。后方及其他部队继续由默认模块管理。

此例必须能验证：多个合法任务可并行，接管可交还，策略可按新情报改计划，订单均通过游戏已有动作。策略空间应允许覆盖所有己方实体和合法动作，原版每阶段可用的常规操作也应从 SDK 可表达。从而可以靠抢矿、局部兵力优势和更少战损获得策略收益。

接口可以证明可表达性、控制权独占与公平边界。**明显强于 Impossible 是策略验收目标，不能从接口推导胜率。** 公平性应先固定双方有效收入、初始资源、房间规则和观测口径。可同时保留两个口径：对比原生 Impossible 时申明它保留原生行为，同权限对比则给双方同一观测约束。验收标准应预先定义“明显”的界线。

## 5. 实施顺序

| 阶段 | 维护者交付 | 策略验收 |
|---|---|---|
| 1. 固定合同 | 六类白名单、固定注册入口、只读观察、强类型意图、正常命令适配，策略仅能链接允许的 SDK 能力 | 空入口运行；一个工厂的小改动可表达；雾下实体和对局配置不通过 SDK 暴露 |
| 2. 开放战术控制 | 接通作战与战术模块，原版招募、两种组更新、补员和召回都尊重接管范围 | 一支突击队独立行动，其他部队由原版规则管理，可恢复控制 |
| 3. 接通经营和运输 | 接通经济、生产、运输模块，按统一账本协调开支，明确乘客和车辆交接 | 扩张、补员、运输和交战能协同；争用资金、工厂或乘客时有可预测结果 |
| 4. 交付策略模板 | 从单工厂调整、单队接管到跨岛突击三个完整示例，每个示例说明所需回调与能力范围 | 作者能从局部改动逐步扩大控制，无需重写基地或运输系统 |

写入目录限制保护开发范围。运行时能力边界另外由宿主执行，因为 Java 的继承白名单本身不限制代码调用其可见的引擎公有方法。
