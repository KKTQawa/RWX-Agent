05 / FINDINGS

只看 Agent 这一侧，
三条结论。

下面三张卡由当前批次的评分产物直接算出，不写地图难度、对手强度或规则设计，只看智能体自己：换了什么工具、延迟多少、挨打之后反应多快。

模型决定胜负，工具影响实时

+5.6

同一个模型（deepseek-v4.1-flash）换工具后的四个 CASE 平均分：Pi 28.4 / DSH 22.8。同一批 task 与 seed，差距只来自工具链。

来源：micro-results.json · records
30 / 30

持续生产 CASE 的行动延迟：DSH 打满 30/30，Pi 只扣 25.0。从看到状态到真正下令这一段，仍是主要瓶颈。

来源：micro-results.json · items.action_delay
−24.4

完整对局里偷袭 v3（单位挨打后仍空闲）平均扣 24.4/50，39/55 局超过 20 分 —— 这是反应速度，不是地图难度。

来源：results.json · v21.items.ambush

06 / START

把你的智能体
带上战场。

准备 Java 25，克隆项目并启动游戏实例。随后把操作文档交给智能体，让它通过 CLI 读取状态并下令。

打开智能体操作指南
QUICK START
# 获取项目
git clone https://github.com/KKTQawa/RWX-Agent.git
cd RWX-Agent

# 使用 Java 25 启动带 CLI 的游戏
.\gradlew.bat :desktop:rwxCliRun
