BLACK-BOX TUNING · HARD-UP

不改引擎源码，
把 AI 的旋钮交给搜索。

Hard-up 是一条黑盒优化路线：引擎与 AI 的决策流程都不动，只把已经暴露的数值旋钮和兵种权重交给 CMA-ES，按真实对局的奖励反向选择参数。本页给出三版参数空间的维度、奖励函数，以及目前实测到的能力上限。

优化器CMA-ES · 逐代采样 + 真实对局对局口径同收入 · 指挥中心胜负 · 90 分钟封顶

01 / SETUP

实验怎么跑

一条只依赖配置文件的搜索回路。优化器看不见引擎内部，只能看到一局结束后的奖励。

SEARCH SPACE

只动已暴露的旋钮

节拍、建造与升级门槛、生产 / 战术参数、建造评分表、Impossible 分支表和兵种权重。数值维度按网格取整，权重按 softmax 解码；引擎里写死、配置不读的 reference 项不计入搜索。

ROLLOUT

每个候选打真实完整对局

一直打到指挥中心被清空；90 分钟仍未决胜记平。同代所有候选共用同一批地图、出生点与种子，槽位按代轮换，避免把出生位差异当成参数收益。

SELECT

CMA-ES 按平均奖励更新

fitness = −mean(R)；一个候选完全没有有效局时记为 +∞。每代 4–20 个候选、每个 3–18 局，6–12 个 worker 并行，单代几十秒到几分钟（取决于地图与是否团战）。

  • ai.json 是「引擎原值基线」：每个数值项的 value 都等于引擎里的原值，所以不调参时不弱于、也不强于内置 Hard；params_Hardupv*.json 只是优化器的默认起点。

  • 兵种权重是 softmax 组：向量里的 logits 决定相对比例，解码后总和保持不变（v1/v2 为 21.00，v3 为 26.00）。

03 / REWARD

奖励函数

三个版本各写一份单局奖励：胜、平、负分档计分，每档再叠加技能 / 时间额度。分数范围刻意压窄，避免一两局极端结果主导整代均值。

  • 军事交换分：只比较双方军事单位的损失造价，等价交换得 0.5，敌方损失越多越接近 1；目前战损由每 500 tick 的单位数量快照估。
  • 速胜分：1 − t / 60min（夹到 0–1）。
  • 存活分：t / 60min（夹到 0–1）。

  • 终局收入占比 X：X = 己方每秒收入 ÷（己方 + 敌方每秒收入）；E = clip(0.5 + 2 × (X − 0.5), 0, 1)。
  • 终局建筑占比 r：r = 己方建筑造价 ÷（己方 + 敌方）；B = clip(1 − 2r + 0.5, 0, 1)，r 越低 B 越高。
  • 速胜分：1 − t / 60min（夹到 0–1）。
  • 存活分：t / 90min（夹到 0–1）。
  • 每代所有有效对局先按批次求均值，再对批次求平均；有效局少于计划局数的 80%（且不超过 min_valid_games，默认 12）时整代中止。
  • 完全没有有效局的候选，fitness = −mean(R) 记为 +∞，不参与更新。

04 / CEILING

现有算法的能力上限

相对游戏内置 AI 的实测最好成绩：Hard-up v1 在 1v1 单场景到过 70%，换全图池回落到 58.5%，对 Very Hard 约 37%。

上限怎么读

  • 70% 是单场景峰值，不是全图池水平。同一份 v1 Gen200 权重，19 图 200 局是 70%，28 图 94 局是 58.5%，双机三场景 600 局是 62.2%。地图池与阵容一换，收益就回落。
  • 对 Very Hard 只有约 37%。Very Hard / Impossible 的差距主要来自写死的收入倍率（1.8× / 3.7×）和分支表的体量优势；同收入下原版 AI 之间长期僵持，所以这个数字更像是「参数层能补多少」的上限。
  • 加维度没有突破这一档。29 → 56 → 85 维，默认参数三版都落在 45–51%；v3 在 2v2 验证能到 62.5%，但同批训练池只有 47.5%，说明地图 / 阵容 / 出生位的方差大于维度收益。
  • 瓶颈在决策结构，不在数值。中后期胜负由原版 UnitGroup 的集结与进攻节奏、BaseZone 的选址与分档决定；这些旋钮写在引擎里，配置层改不动。要推过 70%，需要改官方决策代码（按 UPSTREAM.md 登记）或换真正的策略层。
  • 与评测账本不是同一把尺子。这里的胜率来自同收入真实对局；网页账本的 total-v2.1 是命令 / 事件 / 经济材料评分，胜负本身不进公式。
