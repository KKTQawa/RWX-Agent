# Stage1 v2-provisional：26 局偏差池的临时标尺

版本：`stage1-score-v2-provisional`  
状态：`provisional-frozen`，评测期间冻结，**不得与 `stage1-score-v2` 的分数混榜**。  
入口：`node evaluate/tools/stage1_provisional.js`

这版不是新的正式标准，而是当前没有参照池时的临时标尺。26 局全部是偏差局，只能学到“差的那一端长什么样”，
学不出“什么算好”。因此只重标 f5/f6 的 `hi`，`lo` 保留结构下限，`W`、`λ` 和活跃度闸门都不动数据。

## 1. 为什么只动 f5/f6 的 hi

| 组 | 现状（26 局） | 结论 |
|---|---|---|
| startup `f1` | 8.6–90.3 s，有拉开 | 不动 |
| cycle `f2/f3` | f2 8.0–26.3 s、f3 0.06–18.2 s，有拉开 | 不动 |
| silence `f5/f6` | 旧 `u=1` 分别 11/26、23/26 | 饱和，只重标 hi |

旧 `f5 hi=60`、`f6 hi=45` 是设计先验。26 局里 f5 有 42.3% 顶满、f6 有 88.5% 顶满；`W` 和 `λ` 对顶满样本没有作用，
所以只能改 hi。

## 2. 标定方法

- `lo` 不动，由结构决定：
  - f5 是 B 簇间空窗，B 簇合并阈值是 5 s，所以 f5 的样本天然 ≥5，`lo=5` 就是结构下限。
  - f6 是底层指令间空窗，`lo=3` 对应“一次决策周期 + 一次调用”的物理下限。
- `hi` 取 26 局逐局统计量的 **P90**：
  1. 每局算 f5/f6 的时间加权 P90（间隔自身长度为权重，含末尾空窗）；
  2. 26 个逐局值再取 P90。
- 结果是 **f5 hi=88.568 s、f6 hi=107.472 s**，允许最差 3 局饱和（3/26=11.5%）。
- 不用 P95：这批全是差局，P95 的尾部比“含人类的混合池”轻，会把 hi 抬得过高；f6 尤其会被 235 s 的尾部拖走。
- 剔除每局末尾空窗后再算，26 局的 P90 仍是 **88.568 / 107.472**：hi 不是被 235 s 尾部拖出来的，中段空窗本身就在这个量级。

对照值：

| 量 | f5 | f6 |
|---|---|---|
| P85 | 80.948 | 96.268 |
| **P90（采用）** | **88.568** | **107.472** |
| P95 | 108.536 | 148.940 |

## 3. 冻结项

| 项 | 值 | 原因 |
|---|---|---|
| `W` | `(20, 40, 40)` | 没有同 Agent、同地图重复局，网格会把权重学歪 |
| `λ` | `0` | 线性极限；等参考池再定 |
| 活跃度闸门 | 关闭 | silence 已覆盖低活跃，再加 gate 是重复计罚 |
| `r_min` | 记录 `2/min`，但不启用 | 接近这批最低值 2.49/2.60，只拦真正空转；临时版直接关闭 |
| `T_min` / `N_min` | `300 s` / `5` | 沿用 v2 |

参数在 `config.json` 的 `stage1.v2_provisional.parameters`。`initial` 保留设计先验，`current` 是本版值。

## 4. 结果

| 指标 | 旧 `stage1-v2` | 新 provisional |
|---|---|---|
| 均值 | 35.882 | **40.616** |
| 中位数 | 36.070 | **42.490** |
| 最低 | 16.140 | 16.140 |
| 最高 | 49.680 | 56.320 |
| 胜局均值 | 37.706 | 42.948 |
| 败局均值 | 30.931 | 34.286 |
| AUC（胜/负） | 0.7519 | 0.7368 |

26 局中 24 局升高、0 局降低、2 局不变（已经顶满的最差局）；平均 `+4.734`，区间 `[0, +7.820]`。

饱和验收（每个计分特征 `u=1` 占比 ≤40%；`f4` 仅诊断）：

| 特征 | 旧 `u=1` | 新 `u=1` | max u | P90 u | 判定 |
|---|---|---|---|---|---|
| f1 | 1/26（3.9%） | 1/26（3.9%） | 1.000 | 0.866 | 通过 |
| f2 | 0/26 | 0/26 | 0.922 | 0.779 | 通过 |
| f3 | 0/26 | 0/26 | 0.650 | 0.306 | 通过 |
| f5 | 11/26（42.3%） | 3/26（11.5%） | 1.000 | 0.994 | 通过 |
| f6 | 23/26（88.5%） | 3/26（11.5%） | 1.000 | 0.990 | 通过 |
| f4 | 17/26（65.4%） | 17/26（65.4%） | 1.000 | 1.000 | 诊断（不计分） |

**结论：5 个计分特征全部 ≤40%，不需要为 f1/f2/f3 放宽 hi。**

f1 唯一顶满的是 `Magma-Island-(4p)-20261108--00-05_codex_run-0011`（startup 20.000，f1=90.336 > hi=90）；
f2 最高 u=0.922（26.272 s / hi=30）、f3 最高 u=0.650（18.224 s / hi=35），都还没有顶满。
f4 的 65.4% 是诊断项，不参与验收。

检查可直接从 CSV 复跑，不需要重新评分：

```powershell
node evaluate/tools/stage1_saturation.js
# 写 _stage1-saturation.json / .md；任一计分特征超 40% 时退出码为 1
```

新 `u` 中位数约 0.83，略高于“差局中位 0.6–0.8”的建议值。这是 P90 规则的直接结果：26 局全差，逐局 P90 的 P90
本来就会落在分布上沿。若强行压到 0.6–0.8，hi 要接近 P95，反而把标尺放得太松；本版按 P90 保留。

## 5. 验证

### 5.1 特征相关

新 `u` 的 Pearson 相关：

| | f2 | f3 | f5 | f6 |
|---|---|---|---|---|
| f2 | 1.000 | 0.629 | 0.616 | 0.689 |
| f3 | 0.629 | 1.000 | 0.461 | 0.566 |
| f5 | 0.616 | 0.461 | 1.000 | **0.841** |
| f6 | 0.689 | 0.566 | 0.841 | 1.000 |

f5 与 f6 相关 0.841，silence 组内部仍可能重复计罚。这支持“先冻结 W、不要跑网格”的判断；要拆开只能改特征定义，
不是调 hi 能解决的。

### 5.2 外部效度

- Stage1 新分与 Stage3 v2.1：Pearson `0.1985`、Spearman `0.3183`（n=26）；旧分 Spearman `0.3210`。
  方向为正但很弱，Stage1 主要测实时节奏，不是战果。
- 旧/新 Stage1 排名 Spearman `0.9720`，改 hi 没有推翻排序，只把整体抬高。
- 若把 v2.1 总分里的 Stage1 换成 provisional（Stage3 不变），总分均值 `+1.894`。本版**没有**改写现有
  `score_v21.json` / `_v21-summary.*`。

### 5.3 扰动

P1/P2/P3/P5/P6/R 的完整逐档结果在 `_stage1-provisional-summary.md`。摘要：

| 族 | 结果 | 说明 |
|---|---|---|
| P1 整体后移 5/15/30/60 s | 26/26 通过 | 只 f1 变，S 不升 |
| P2 间隔 ×1.25/1.5/2/3 | 26/26 通过 | f1–f6 同步变大，S 单调下降 |
| P3 中段插入 15/30/60/120 s | 26/26 通过 | f5/f6 上升，S 不升 |
| P3 末尾插入 15/30/60/120 s | 15/30/60 s 各失败 1/2/1 局，120 s 全过 | 见下 |
| P4 删 A 25/50/75% | 只报告 | 最多 `+1.88`，删样本会改变 f2/f3 中位 |
| P5 大批 + 长停顿 | 26/26 通过 | 平均 `−33.045`，负对照成立 |
| P6 空窗塞 A | 26/26 通过 | 平均 `−0.072`；尾部刷 A 恒 0 |
| R 更快（ρ=0.5/0.25） | 通过 | 平均 `+20.702` / `+38.202`；ρ=0.25 只有 10 局仍 ≥300 s |

**P3 末尾短插入的异常**：时间加权 P90 以间隔长度为权重；在末尾追加一个 15–60 s 的短样本，会给“低于当前 P90”的部分
增加权重，累计到 90% 时反而可能落到更短的间隔上，所以 f5/f6 偶尔轻微下降（最多 `+0.58` 分）。中段插入不出现这个
问题。这是加权 P90 的固有性质，不是 hi 标定错误；要让末尾插入严格单调，需要改统计量或规定插入长度大于当前 P90，
本版没有改设计。

### 5.4 块自助

对每局 f5/f6 的间隔序列做 5 块自助（500 次），只重算 silence 组：

- S 的块内标准差中位数 **1.393**，最大 **3.671**；
- 相邻局分差中位数 **0.860**；
- 比值 **1.619 > 1**。

也就是说，**局间排序不可信**：silence 组自身的抽样波动大于相邻两局的分差。这不是 hi 调坏，而是 26 局样本量和
f5/f6 长尾造成的；报告里不应把相邻名次当稳定差异。

## 6. 边界与后续

- `lo` 没有数据来源，仍是结构下限；绝对刻度（“什么算好”）没有校准。
- 没有人类局或固定节奏 bot，做不了“人类 `u ≤ 0.3`”的正对照。
- 这是同一批 26 局的 **in-sample** 标尺，不是泛化验证；它只保证“在这批里不再顶满”，不保证对新局公平。
- 这版只在当前 26 局池子里有相对意义；新增参考局后必须升版本号，旧分不能混比。
- 性价比最高的补充是 2–3 局人类局 + 一个固定节奏脚本 bot；有了它们，hi 大概率要收紧，同一批局的分数会下降。
- 正式切换 v2.1 总分到 provisional Stage1 是另一个版本决定；当前只提供平行产物，不改现有 `score_v2.json` /
  `score_v21.json`。
